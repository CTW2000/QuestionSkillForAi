# 提问模板

> **用途**：写代码前贴进 prompt 定调；写完后当自查表；复盘时逐条走。
> **信念**：多数 bug 不是"想到了但写错了"，是"没想到要问这一层"。**问法决定能不能被想到。**
> **纪律**：每条回答都要**指出代码位置**；指不出来就明说"没有"，不接受"应该没问题"。
> **编号**：`T*` 是手法，`N.M` 是问题。**编号永不复用**，删掉即作废；**编号是身份不是位置**，顺序可按逻辑调整。
> **标记**：`⟨前端⟩`/`⟨后端⟩` 是**镜头**——只在该形态下问得动，跨平台时换用同行给的对应问法。`[grep]` 表示这一问可以机械化执行，不必靠通读。命中记录见文末「计分」。

## 通用变换（把弱问法改成强问法）

- **T1 要位置，不要判断** — 不问"有没有问题"，问"谁保证的？把那行贴出来"。
- **T2 把"有没有"换成"有几处"** — 计数强制枚举，枚举强制遍历；"有没有"找到一个正例就收工。
- **T3 问概率，不问可能性** — 先回答"对方能不能自己挑时机"，再谈概率。
- **T4 要能让它变红的那个改动** — 不问"覆盖了吗"，问"把实现改错，哪一行断言会红"。
- **T5 分开"写下来"和"被强制"** — 规则写在哪一层？违反时最早在哪一步被拦住？
- **T6 先问能不能消除，再问怎么测** — 让错误状态无法构造的结构，强过任何检测。
- **T7 给一个说"没有"的出口** — "确实没有就说『没有，因为X』，不要为了凑答案而编。"
- **T9 用「最坏后果」决定投入多少严谨度** — 先问"这段要是错了最坏会怎样"，再决定这次在哪几条上花力气。严重度不只用来给发现排序，更用来**分配注意力**。
- **T8 让它反驳自己** — "这个结论如果错了，最可能错在哪一步？"以及"你定级依据的那句理由，本身成立吗？"

## 一、时序与并发（TOCTOU）

- **1.1** 这里的"检查"和"依据检查结果动手"是不是两步？中间隔了什么？靠什么保证原子——唯一约束 / CAS / 原子脚本 / 悲观锁 / 什么都没有？
- **1.9** 能不能把"检查"和"动手"合成**一个原子的占坑动作**——先申请额度 / 先插一行 / 先 CAS 改状态，**占坑成功本身就是许可**，而不是先看一眼再决定？占没占上**凭什么判定**：影响行数 / 唯一键冲突 / 返回值，还是又去查了一次（那就退回两步了）？
- **1.10** 占坑之后的动作失败了，**坑还回去吗**？把补偿的那行指出来。不还，会不会把额度或资源永久占死？还了，会不会让"故意失败"变成绕开限制的手段？
- **1.2** 读出一个对象 → 改几个字段 → 整体写回：**谁保证这中间没人动过这行**——乐观锁版本列 / 行锁 / WHERE 条件+按影响行数判定 / **什么都没有**？把那一样东西的位置贴出来。另外：读与写之间**夹没夹一次网络调用**（HTTP、发信、发短信）？夹了的话窗口是秒级不是微秒级，单独标出来。反向陷阱：想把某个字段清空，做得到吗？ `[grep]`
- **1.11** 这个原子动作（CAS / 占坑 / 条件更新）有**几条入口**？把**跳过它的 early return / 短路分支**逐条列出来——"看到已经是目标状态就直接放行"算不算一条？同一个类里做同一件事的兄弟方法，是不是**每一个**都走了这条原子路径？ `[grep]`
- **1.12** 多个相关的值通过**各自独立的 getter / 各自一次查询**读出来时，调用方拿到的是一份**撕裂的快照**吗？（1.2 管写侧，这一条管读侧）
- **1.3** ⟨前端⟩ 守卫钉在"状态"上还是"过程"上？危险窗口从哪一刻开始——渲染到某一步，还是请求发出那一刻？⟨后端⟩ 读出来的这一行，到"依据它写回去"之间跨了几次外部调用、几次事务边界？
- **1.4** 拿到锁之后，锁外读到的东西有没有重新读一遍？
- **1.5** 有没有"先动手、事后刹车"的地方？刹车失败时，已经做掉的那一半怎么办？
- **1.6** ⟨前端⟩ 用户点了取消，在途请求会被中止吗？还是界面消失了、副作用照样发生？
- **1.7** 同一个请求重放两次会发生什么？把防重复的那道防线指出来。
- **1.8** 这个竞态是随机的，还是对方可以挑时机的？如果能挑，一天能打多少次、命中率多少？

## 二、数据源与状态

- **2.1** 把这个事实在系统里的**所有表示**列出来，标出各自是什么时候、由谁算出来的。**只有能够不一致的才算**——同一次查询的多个投影是一份，不是两份。
- **2.9** 列完之后逐个问：**这一份谁写？** 把写入的那一行贴出来。写入点只有初始化那一处的，它不是状态，是**伪装成状态的常量**——而读它的那个判断等于恒真。 `[grep]`
- **2.2** 屏幕上（/日志里/响应里）的这个值，和系统做决定时用的那个值，是**同一次计算**出来的吗？中间隔了多久，这段时间谁能改它？
- **2.3** 这里存的是**用户点击那一刻的意图**，还是**当前的真实状态**？两者分叉时谁赢？
- **2.4** 这两份能不能**收口成一处**？有没有办法直接用手里已有的真实数据，而不是再维护一个常量？
- **2.5** 这个**常量、集合、或判定规则**（哪些状态算"处理中"、什么条件下允许动钱）在系统另一端有没有对应的一份？**SQL 字符串里的那一份也算**（注解 SQL 里的 `IN ('A','B')` 编译器管不着、IDE 搜不到）。改一端会不会漏另一端？ `[grep]`
- **2.6** 这份数据**允许陈旧多久**？先归档再谈实现：**必须实时**（决策 / 资金 / 权限的依据）/ **可以滞后几秒**（列表、计数、统计）/ **无所谓**（装饰性）。默认不是"越新越好"，而是"先把要求说清楚"。
- **2.7** 这份派生数据（缓存列 / 聚合计数 / 对账不变量）**由谁重新算**——⟨前端⟩轮询 / 窗口重新聚焦 / 用户操作后 / 服务端推送；⟨后端⟩哪一个 `@Scheduled`、哪一个 webhook、哪一次用户请求。把那个类名写出来。**「没有人」是必须放在明面上的选项**，不是枚举末尾的兜底。
- **2.8** 如果它们不同步会怎样？**分三档回答**：① 只是难看 ② **界面在撒谎，用户会据此做出错误决定** ③ 会导致错误的资金或权限动作。第②档最容易被低估——系统行为可能完全正确，但用户是在错误信息下按的确认。**定 ③ 之前先指出这条路径上真正改动金额或权限的那一行，指不出来就不是 ③。**

## 三、约束的执行力（写下来 ≠ 被强制）

- **3.1** 这条规则现在写在哪一层——注释 / 文档 / 变量名 / 类型 / 运行时校验 / 数据库约束？
- **3.2** 有人违反它时**最早在哪一步**被拦住：编译期 / 测试 / 启动时 / 运行时 / 永远不会？
- **3.3** 需求逐条对照——**证明"没有"要遍历全库，所以必须换成可收敛的三步**：
  **a. 先建搜索词表**：给需求每一条标注「它落地后必然存在的一个可搜实体」（一张表 / 一个路由 / 一个枚举值 / 一个常量）。标不出来的直接归入"本次不查"。
  **b. 逐条只做两个动作**：grep 那个实体 →（命中）打开唯一的写入/匹配点，**核到字段**。命中不等于实现。
  **c. 报数**：本次对照 N / 共 M 条，未对照的逐条列出原因。**不给分母，「都实现了」和「我只查了 8 行」看起来一模一样。** `[grep]`
- **3.4** 代码注释里"为什么这么做"的那段理由，**现在还在支撑一个决定吗**？（这段话如果是假的，哪个设计选择会立刻站不住？）标了「历史注 / 曾经」的不算——**过时不是问题，被当成现行依据才是**。
- **3.5** 这个约束能不能交给类型系统，让非法状态**根本无法构造**？
- **3.6** 这条规则有几条实现路径？每一条都过同一个关卡吗？绕过的那条会不会**连报错都没有**？
- **3.7** 客户端做的这个检查是安全措施还是引导？绕过它之后，服务端会拦吗？
- **3.8** 这个关卡（鉴权 / 二次验证 / 限额 / 审计）挂在哪些入口上？**把它保护的入口和它没保护的同类入口各列一遍**——判断"同类"用的是什么判据，这个判据写在哪里、由谁维护？漏挂一个入口，是**功能走不通**（会被立刻发现）还是**静默放行**（永远不会）？ `[grep]`

## 四、凭据、密钥与生命周期

- **4.1** 同一个秘密在不同存储介质里的保护级别一致吗？（一处加密、另一处明文，等于没加密）
- **4.2** 这个存储里哪些是**短命的过程状态**、哪些是**长期凭据**？"反正这里本来就有敏感数据"这句话，拆开看还成立吗？
- **4.3** 这东西创建之后，什么情况下应该作废？**把作废的触发点全部列出来**，逐个对照代码里有没有。
- **4.4** 已经签发出去的凭证，在签发之后主体状态变了（停用 / 删除 / 改密 / 降权），谁来发现？**签发时校验过 ≠ 使用时仍然成立。**
- **4.5** "一次性"是被谁执行的？把执行它的那行代码指出来。
- **4.6** 这个秘密会不会出现在日志、异常信息、`toString`、响应体、URL 里？
- **4.7** 恢复通道（恢复码 / 客服重置 / 备用邮箱）的强度是不是低于主通道？攻击者会走哪条？
- **4.8** 解密或校验失败时，有没有一条"降级"的静默回落路径？有没有一条路能让人在不知道旧密钥的情况下换成新的？

## 五、判据与证据（测试真的在测那件事吗）

- **5.1a** 对这段实现里的**每一个** `return` / `throw` / 写操作，指出**哪个测试文件的哪一行断言**会因为它消失而变红。**逐条列，指不出来的就写「没有」。**
- **5.1b** 这个方法在全仓被引用了几次？其中几次是 `when/thenReturn`、`verify` 这类**桩**？两个数字相等时，它的实现**从未被执行过**——这一条不用跑测试，`grep` 就能定。 `[grep]`
- **5.2** 测试钉的是"调用发生过"还是"调用发生在正确的位置"？把它挪到后面一步，还绿吗？
- **5.3** 断言里的这个值，是从**被测代码**算出来的，还是从**测试的桩**算出来的？若确由被测代码算出，再问一句：**有没有另一条测试证明这个函数不是常量、不是恒等映射**？有就不算自证；没有，才是。
- **5.4** 测试的输入集合能走到那个分界点吗？**把唯一能区分对错的那个输入写出来**，它在集合里吗？
- **5.5** 这条断言/不变量**有没有可能失败**？**把能让它失败的那个实现写出来**。写不出来，它就没在守任何东西。（写不出来时的正解未必是删——也可能是把断言改成真的、或修好那个匹配空集的规则）
- **5.6** 测出来的这个「上限 / 强度」，是**被测系统**给的，还是线程池、连接池、构建 profile、include 模式给的？**把定这个上限的那一行指出来。**（并发用例还要问：worker 有没有用门闩统一起跑？线程数够不够多到能撞出交错？）
- **5.7** 缺陷落在单点上还是**状态组合**上？如果是组合，例子测试结构上就够不到——穷举的动作集里有没有"**世界在变**"（服务端被别处改、定时器到期、另一个客户端在操作）？状态空间小到能走完时，别赌随机抽样。
- **5.9** 这个方法在测试里是被**执行**了，还是只被 stub / verify？**把真正 new 出被测对象并调用它的那一行指出来。**指不出来，它的每条分支都是零覆盖。 `[grep]`
- **5.10** 这道守卫（ArchUnit 规则 / 覆盖率闸门 / 变异门禁 / 登记表 / lint 配置）的**匹配集合有几个元素**？把它今天实际管住的类名列出来。**列出来是空的，这道闸门恒绿。**（本节的扫描范围包含 `pom.xml` / CI 配置，不只是 `src/test/`） `[grep]`
- **5.11** 这条断言是在**主线程**里执行的吗？异步回调、线程池、事件监听器里抛出的断言错误，**测试框架收不到，测试照样绿**。
- **5.8** 这个结论是哪一档证据：受控复现 / 生产日志 / 局部实验 / 读代码推断？

## 六、默认值、兜底与未知态

- **6.1** 这个兜底分支（`else` / `default` / 链条末尾）会做什么？如果它是破坏性的，靠什么防守？**"上层碰巧到不了"不算防守。**（只报**改状态 / 动钱 / 放行 / 发外部调用**的兜底；只产出展示文案的不计——现代语言的穷尽式 `default` 是语法强制，不是设计选择）
- **6.2** ⟨前端⟩ 这个布尔量把"未知 / 加载中"和"已知的另一种"压成一种了吗？⟨后端⟩ 这个函数返回的 `null`（或这个字段的空值）**一共代表几种情况**？逐条列出来。超过一种时，把**代价最高的那一种**写出来——上游能区分它们吗？
- **6.3** 遇到未知值或新增枚举时往哪边倒？**两种说错话的代价对等吗？**
- **6.4** 这条"未知时怎么办"的规则只适用于哪一帧？会不会被套到它不适用的帧上？
- **6.5** 失败时是抛异常还是静默 `return`？上游会把静默 return 当成成功吗？
- **6.6** ⟨前端⟩ 一个**错误的正面反馈**会不会比没有反馈更糟——它是不是把"该去补救"的线索也一并抹掉了？⟨后端⟩ 这次返回的 2xx / ack，会让**对端**认为事情已经做成了吗？把"做成了"和"没做成"在响应上的差异指出来——**没有差异时，对端会停止重投**，这条线索还有别的地方能捞回来吗？
- **6.8** 这个未知值在系统里有**几条消费路径**？把每一条的兜底方向写出来。**有没有一条抛、另一条静默**？倒向不一致时哪一条是对的，另一条为什么活到了今天？ `[grep]`
- **6.9** 把这个模块的**开关类配置默认值**全部列出来，逐个标注倒向安全还是倒向方便。**有没有一个开关的默认值让另一个开关失效**？把那两行贴在一起。 `[grep]`
- **6.7** 输入过滤 / 净化器放行的字符集，和后端实际接受的格式一致吗？

## 七、复用、漂移与文案

- **7.1** 这段代码是从哪儿抄来的？抄的时候里面的**字面量**（标题、提示语、常量、日志前缀）跟着改了吗？**抄了但指明出处的不算问题**——要问的是：两份现在**有没有分叉**？把差异逐条列出来，每条说明是有意还是漏改。
- **7.2** 这条注释**照着做会出事吗**？（比"过时"更严重的是"引向错误改法"）
- **7.3** 有没有"目前只有一个消费者，先放这儿"这类注释？第二个消费者已经出现了吗？
- **7.4** 有没有拿**人类可读的文案**当控制流用？（判断错误信息里有没有某个子串）
- **7.5** 同一个形状在别处还有几处？**先把"形状"落成一个可 grep 的锚点再计数**：① 这份数据最终落到的**列名 / Redis 键前缀**（DDL 里每个 `UNIQUE KEY` 都在断言"这几列算出来的值可比"，把写它的代码全列出来）② **同名方法的函数体哈希**（只看同名不同体的组）③ **字面量**（错误码、前缀、常量值）。三者都拿不到锚点，说明这个"形状"还没定义清楚。**报数字，不报"还有几处类似的"。** `[grep]`
- **7.6** 两个独立的地方在改同一个东西吗？它们的执行顺序谁定？
- **7.7** 这个 bug 修了一半吗？（这一处区分了，另一处没跟上）**做法**：`git log --grep 'fix('` 读正文——好的提交信息会直接写出对照面；`git log -S` 是第二手段。 `[grep]`
- **7.8** 这次改动里"不在本次范围"的部分是什么？**写下来**，否则三个月后没人记得。
- **7.9** 这段注释把**承重点指在哪一层**？把它指的那一层删掉，行为真的会变吗？（`7.2` 预设注释是**指令**；这一条针对注释是**归因**的情形——注释说保护来自 A，实际承重的是 B。**它的破坏力在于：任何"不动 A"的改动都可以合法地把 B 改掉。**）悬空的 `@link`、指向不存在的方法名，是这类漂移的硬证据。 `[grep]`
- **7.10** 有没有"**已普查过所有写路径**""目前唯一入口""必须与 X 一致"这类**长期有效的强断言**？普查是哪一天做的？今天还成立吗？（比"先放这儿"这种暂时性声明危险得多——它会让下一次评审把一整类风险从评估里划掉）

## 八、信任边界

- **8.1** 这个值是谁给的——用户 / 另一个服务 / 我们自己算的？跨边界的那一行有没有重新校验？
- **8.2** 客户端传上来的这个字段，服务端信了吗？如果服务端本来就能自己算出来，为什么还要收？**能不能结构上就不给这个字段？**
- **8.3** 归属 / 租户隔离**由哪一层加**——拦截器 / SQL 里显式写的 / 没有？把它在租户表登记里的那一行贴出来。**不在任何登记里的表，才继续往下问**（有全局拦截器的项目里，照字面看每处 `selectById` 都像漏洞）。
- **8.4** 把「不存在」和「存在但不属于你」两条路径返回的那两行**并排贴出来**。（单看一句错误文案永远像候选，成对看才可判定）

## 九、资金与账务

- **9.1** 金额用什么类型表示？把所有出现 `double` / `float` 的金额字段列出来。做**除法或乘汇率**的每一处，`scale` 和舍入模式是显式指定的，还是靠默认？**跨进程传输时**（JSON / protobuf）金额是什么类型——不同语言的反序列化精度不同，浮点会在边界上悄悄变形。 `[grep]`
- **9.2** 舍入误差往哪边倒——对我方有利还是对用户有利？同一笔钱在整条链路上被舍入**几次**？多次舍入的累积差额由谁兜？
- **9.3** 金额和币种是**成对传递**的，还是有裸的数字在函数之间流动？两个不同币种的金额相加，会报错还是会静静地算出一个数？
- **9.4** 小数位数是硬编码 2 位，还是按币种取？（JPY 0 位、KWD/BHD 3 位）数据库列的 `DECIMAL(p,s)` 与代码的 scale 一致吗——入库时会不会被**静默截断**？系统里"元"和"分"两种单位混用吗，转换发生在哪几处？
- **9.5** 从用户看到的报价 → 提交 → 落库 → 发给服务商 → 回调入账，金额被**重新计算过几次**？把每一次重算的位置列出来，标出哪几段是透传、哪几段是复算。
- **9.6** 能不能让金额在整条链路上是**同一个不可变值**——一次算出、绑定指纹、之后只搬运不重算？如果做不到，是什么拦住了？（这一问要的是**结构性保证**，不是"我们会小心"）
- **9.7** 一笔业务的所有分录加起来等于零吗？`总额 = 本金 + 费用 + 汇差` 这个等式**在代码的哪一行被断言**？拆单 / 分账之后各部分之和还等于原额吗，除不尽的余数给了谁？
- **9.8** 这个写操作的**幂等键**是什么？谁生成的（客户端还是服务端）？作用域多大（全局 / 租户 / 用户）？留多久？**幂等键相同但请求体不同**时，是返回上次结果还是报冲突？（返回上次结果 = 用同一个键把另一笔钱吞掉）**在几层强制**——网关 / 业务服务 / 调用服务商那一层？只在一层拦，另外两层就是敞开的。**唯一约束落在哪两列**，把 DDL 那一行贴出来。 `[grep]`
- **9.9** 服务商的回调会重发吗？重复处理会不会**重复入账**？回调**乱序到达**（先收到"成功"、后收到"处理中"）会不会把终态改回去？
- **9.10** 扣余额 / 占额度是"读 → 判断 → 扣"，还是**原子扣减 + 按影响行数判定**？同一笔资金能不能被两笔业务同时占用？（与 `1.9` 同源，这里问的是资金侧的具体形态）
- **9.11** 累计退款能超过原单吗？谁保证？金额允许传**负数**吗——负数退款会不会变成收款，负数手续费会不会变成给用户送钱？
- **9.12** 外部支付返回**超时 / 未知**时，本地记成什么？**在支付里 UNKNOWN 比 FAILED 危险**：当成失败处理，钱可能已经出去了。这条路径上有对账兜底吗，还是就地拍板？
- **9.13** 谁是资金状态的**权威**——我方还是服务商？两边不一致时以谁为准，代码的哪一行体现了这个选择？**终态还能被改回非终态吗**？
- **9.14** 资金变动是 **append-only 流水**，还是直接 `UPDATE` 余额字段？能不能只凭流水重建出当前余额？如果不能，余额错了怎么发现？

## 维护约定

**加问题**
- 新 bug 先问：**它属于已有的哪一类？**属于 → 什么都不用加；不属于 → 才考虑加一条新问题。
- 每条新问题必须是**强问法**：要位置、要计数、要反例、要分档，而不是能用"是/否"打发的。
- 发现一个"换个问法就问出来了"的时刻，去补 `T*` 通用变换——那里比问题清单更值得投入。
- **平台绑定的问题不要改写成"通用措辞"**——那会同时削弱两边。改用**镜头**：`⟨前端⟩…⟨后端⟩…` 同一编号下并列两种问法。第九节「资金」本身就是一个领域镜头，以后加「移动端」「数据管道」同理。
- **能机械化的标 `[grep]`**，并在问题里写明锚点是什么（列名 / 键前缀 / 函数体哈希 / 字面量）。一条说不出锚点的"枚举题"，在大仓里等于没法执行。

**计分**
- **编号永不复用。** 删掉一条，它的编号一并作废，新问题取本节下一个没用过的号。否则历史计数会张冠李戴。
- **只有真的发现了问题才 +1。** 扫了没发现，不计；发现的是已知问题，照样计——它证明这一问有鉴别力。
- **同时记严重度，不只记次数。** 低频高危的问题（凭据、越权、资金）会被纯次数排名系统性地压下去，而那恰恰是最不该删的一类。
- **每次扫描都要登记用了哪几节**，否则"0 命中"无法区分"没采样"和"低价值"。
- **命中榜数据够了之后，回头校验「快速十问」**：如果某个不在快速十问里的编号，命中次数与严重度已经超过十问里的某一条，考虑换下去。十问本该是**当前证据下最高置信度的那十条**，不是一次定好就不再看。赶时间的场景（卡合并、快速自查）优先问命中榜前列的编号；从容复盘时才把 0 命中的也走一遍。

**规模与删除**
- **没有硬性条数上限。** 问题越攒越多是好事——它意味着采样面在变宽。为守上限而删掉的，恰恰是还没攒够数据的那些。
- 一次扫不完就**分派子代理**，**按节切，不要按编号平均切**：同一节共享材料（五要读测试，七要读注释与复用点，三、四要对着需求读，一、二、六、八读实现与分支），混装会让每个代理都被迫读一遍全部代码。
- 每个子代理都要带上【规则】那四行，否则它会退回"应该没问题"。各自只报自己那几节的编号与严重度，主会话汇总去重。
- **删除是例外，必须先跟我确认。** 只有同时满足「被问过很多次仍 0 命中」**且**「从未命中过中危以上」才提出来问，**不要自行删除**，也不要凭印象删。
